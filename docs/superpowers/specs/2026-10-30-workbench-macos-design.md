# infrafile 工作台：React + Radix Themes 与 C 三栏布局

状态：设计草案，待用户批准；不授权实施、发布或真实台账操作。

## 目标与已确认的选择

用户主要在 Mac 上使用工作台，希望查看资产和巡检结果，快速发现有问题的资产，再进入详情了解原因。当前界面的视觉层级和桌面布局需要改善。

用户明确选择：

- 使用 React + Radix Themes。
- 采用 C「Finder 式资产浏览器」：左侧选择资产类型，中间浏览资产，右侧常驻详情。
- 当前先讨论与确认设计，不实施应用改动。

三栏布局服务于「发现资产问题 → 选中资产 → 查看结论与依据」；不以装饰性材质或仪表盘图表作为改版重点。

## 当前基础与边界

工作台已有 `/assets`、`/inspections`、`/changes` 三个页面。Go 模板与原生 JavaScript 调用同源接口，静态资源嵌入 Go 二进制。会话、配对、来源校验、CSRF、读取范围和编辑事务由 Go 实现。

- 资产详情通过 `show` / `context` 展示登记、直接关系、观测和检查资格。
- 巡检来自共享 `inspect`：执行结果、覆盖、风险、豁免与已保存历史有不同含义。
- 变更页保留问题历史、云执行回执，以及 `--allow-edit` 显式启用后的台账预览、审阅、提交和恢复。
- `list` 返回目录，不提供单资产巡检结论。三栏列表上的状态摘要需要一个有界的只读汇总接口。
- 当前 CSP 不允许任意行内脚本和样式；引入组件库不能靠普遍放宽策略完成。

依据：[工作台](../../serve.md)、[inspect](../../json/inspect.md)、[context](../../json/context.md)、[change](../../json/change.md)，以及 `cmd/infrafile/serve_http.go`、`internal/audit/inspect.go`。

## Approaches：已比较的路线

### 技术

| 路线 | 取舍 | 决定 |
| --- | --- | --- |
| 原生 HTML/JS + Web Awesome | 可逐步接入，减少迁移；现有页面状态与 DOM 组织仍需维护 | 未选择 |
| React + Radix Themes | 增加前端构建与页面迁移，获得统一的组件和主题基础 | 用户选择 |
| React + shadcn/ui | 定制自由度高，但组件源码和定制内容由项目维护 | 未选择 |

### 布局

| 路线 | 取舍 | 决定 |
| --- | --- | --- |
| A：资产表 + 按需详情侧栏 | 便于横向比较多个资产，详情需要打开 | 未选择 |
| B：巡检问题收件箱 | 适合逐项检查问题，默认不呈现完整资产目录 | 未选择 |
| C：类型、资产列表、常驻详情 | 切换资产时上下文稳定；横向分栏限制列表字段数量 | 用户选择 |

用户选择的是 C 的结构与浏览方式，未将草图中所有文案、颜色、尺寸或虚构检查结果批准为最终规格。

## 交付范围

本设计覆盖一次工作台前端迁移：统一配对页与三个已有页面的视觉，重点实现 C 资产页；巡检页与变更页复用既有功能与判断。需要新增前端构建步骤，以及只读资产摘要接口。

保留现有 CLI/MCP JSON、资产数据格式、服务端认证、默认只读边界、可选编辑和云操作边界。最终用户仍直接运行单个 Go 二进制，无需 Node 或外部 CDN。

本轮不新增采集器、浏览器触发同步/巡检执行、健康评分、自动修复、批量云操作、定时刷新、多用户权限、原生 macOS 壳或系统菜单。既有变更功能不能因草图未绘出而被删除。

## 资产页交互

以下细节是设计者的建议默认值，随本设计一起交由用户确认。

### 左栏：入口与范围

顶部显示台账名称，保留资产、巡检、变更三个一级入口；会话与退出位于次要位置。资产页包含全部资产及六种既有类型：Account、Server、Domain、Resource、App、Repo，界面使用中文类型名称。

默认显示在用资产，提供明确的归档筛选；已有链接指向归档资产时允许查看，并显示归档状态，不自动启用或改动该资产。

### 中栏：资产与问题摘要

- 初始选择全部类型，在用资产按「已确认风险 → 待核实 → 范围内通过」排序，同组按主键稳定排序。
- 名称作为主文本；类型、状态和一条最重要的原因作为辅助信息。状态必须带文字，不能仅用颜色表达。
- 搜索沿用名称/主键/标签语义；类型、在用/归档和状态筛选可以组合。状态筛选包括全部、有风险、待核实、范围内通过。
- 每条资产可同时保留风险和未知数量；风险优先级较高，但不能遮蔽它仍有未知检查的事实。
- 未选择资产时，在有完整摘要的当前结果中自动选择第一项；空列表显示明确空态，清空右侧。已选资产被筛掉时，提示选择已变化，并选择新结果第一项。
- 返回列表、切换详情和打开关联资产时保留当前搜索与范围；对有效但不在筛选结果中的链接资产，显示范围外提示和清除筛选入口，不悄悄改写筛选。
- 支持鼠标和键盘选中；焦点留在列表供连续切换，进入详情有明确的键盘路径。

筛选控件和重新读取入口放在紧凑工具栏。重新读取仅加载已保存结果，不能暗示执行了新的采集或巡检。证据有效期沿用默认 7 天，并允许修改。

### 右栏：先解释问题，再提供背景

顶部显示资产名称、主键、在用/归档及巡检结论。内容顺序为：

1. **巡检结论**：全部未豁免确认风险与待核实项，先显示摘要，按需展开每项依据；不只展示一个问题。
2. **判断依据**：每项检查的登记期望、可匹配的保存观测、原始证据时间、资格、来源和 TTL。来源未匹配或不完整时显示原因，不制造可比较值。
3. **资产信息与直接关系**：完整脱敏登记字段、一层引用/被引用关系；关系可选中跳转。
4. **历史与原始证据入口**：跳到当前资产的巡检/变更范围，复杂 JSON、检查代码和完整证据可展开。

近期执行、检查资格、发现和历史状态保持各自含义。原始时间可辅助显示相对时间，但完整时间与时区必须可查看；不同证据时间不能压成一个冒充共同更新时间的值。

切换资产立即标出加载状态并清空旧详情；取消旧请求，并校验当前选择和请求序号。旧响应不得覆盖新选中的资产。401 或读取失败清空对应数据，给出重新连接/重试入口。

## 状态语义与只读汇总

列表状态由服务端提供，浏览器不复制一套巡检资格规则，也不根据 HTTP 200、零 findings 或成功采集回执直接标绿。

### 只读资产摘要接口（设计者建议）

增加仅用于工作台的同源 `POST /api/asset-summaries`，沿用认证、CSRF、严格 JSON 输入、读取隔离和取消/超时机制。参数复用已有 `key/labels/kind/max_age_days` 的选择语义与校验；不增加任意路径、地址或命令。

返回 `version`、`as_of`、`max_age_days` 和按主键排序的 `rows`。每行包含目录所需的主键、类型、标签、归档标记，以及当前单资产范围的 `ok`、coverage/risk 计数、执行资格、简短原因和证据时间信息；不包含完整 spec、secrets 引用或观测原文。

- 每行必须等价于相同已发布输入代次、时间和 TTL 下对该 key 的共享单资产 `inspect` 判断。
- 同一请求固定读取代次和时间；复用不可变输入准备结果，避免为每个资产重新读取所有快照/运行全部规则。若需拆出准备与投影步骤，沿用现有算法与校验，保留 CLI/MCP 输出兼容。
- 不能直接把全局 `inspect.ok` 分给每个资产，不能只按 target 字符串过滤后自行重算成功；共享实例、归档、NA、豁免及范围相关规则须与单资产结果一致。
- 全局实例/集合问题保留在巡检页，不能无依据归给所有资产；资产行只反映明确属于该资产范围的结果。
- 不在浏览器对所有资产逐项请求 `context` 或 `inspect`。打开详情才请求该资产的 `context`；超过 context 限额时沿用有界分项读取，拒绝或缩小范围，不静默截断。
- 响应上限和超时沿用工作台已有 4 MiB / 30 秒限制；超限整份失败并提示缩小类型/标签范围。未经完整汇总的目录可以显示，但所有行须明确「状态未读取」，禁用依赖状态的筛选，不保留上一次颜色冒充本次结果。

### 列表分组

| 摘要 | 条件 | 展示 |
| --- | --- | --- |
| 已确认风险 | 单资产报告 `risk.confirmed > 0` | 红色标签；若同时有 unknown，另列未知数量 |
| 范围内通过 | 单资产报告 `ok=true` | 绿色标签，明确只覆盖当前配置范围 |
| 待核实 | 报告已生成，但既无未豁免确认风险也未满足 `ok=true` | 中性/警示标签，按原因说明未知、未配置、不支持、全部不适用、执行资格不足等 |
| 状态未读取 | 未取得有效报告，或本轮读取失败 | 加载/失败状态，不参与通过统计 |

豁免、NA 和覆盖数单独保留，不将它们自动当成通过；UI 分组遵从返回的正式结果，不改变现有业务规则。查询详情与列表若来自不同代次或时间，各自显示时间并允许重新读取；不得假装两次请求构成一个事务。

草图中的 TLS、域名到期等问题只是示意；实施时仅显示当前真实契约提供的检查。App、Repo、Account 等未支持的健康检查不会因改版获得新的通过结论。

## 巡检与变更页

巡检页保留当前范围、最近执行、固定覆盖分母、确认风险、未知/豁免、已保存问题历史和提示缺口。优先展示需要关注的项目；全局实例/集合问题与资产项分别呈现。资产项可返回三栏页的对应详情，范围跨页保持。

变更页保留问题变化、已清理历史边界、云计划/回执查看、`uncertain` 提示，以及完整台账预览/审阅/提交/恢复流程。仍无云执行、自动 push 或同步按钮。默认只读，编辑入口按服务端 `enabled` 状态展示；不能绕过 `--allow-edit`、review digest 或恢复检查。

配对与退出继续使用服务端表单与现有凭据处理方式；视觉可以统一，但成功会话不写 localStorage、URL 或日志。

## 视觉与适配

建议使用系统字体、中性灰背景、单一蓝色强调色、小到中等圆角和细分隔线。内容区实色，装饰性玻璃和大面积阴影不作为设计目标。风险、未知、通过颜色保留文字说明；三栏不机械堆叠卡片。

Radix Themes 优先使用原生 props、主题变量和组件结构；自定义 CSS 主要负责三栏、列表及必要布局。亮/暗模式跟随系统，显式偏好可选系统/浅色/深色；如持久化只保存外观偏好。

桌面下侧栏、列表、详情独立滚动，建议初始宽度约 180 / 300 / 剩余空间，具体值由可读性验证决定。首轮不做拖动调整宽度或任意自定义布局。

窄窗口逐步收起侧栏，进一步变窄时以列表 → 详情的单栏导航替代强塞三栏；返回后恢复选择与滚动位置。保留现有移动端可用性。列表焦点、菜单、对话框、筛选与空态须可用键盘操作，更新不反复抢焦点。

## 技术组织与分发

React + Radix Themes 已由用户选择。以下是设计者为减少维护给出的默认方案：

- 使用 TypeScript 和 Vite 构建静态资源；无需 SSR、Node 服务、Next.js 或新后端。
- 三个固定路由沿用原地址与 `key/days/issue` fragment 兼容；不因这次迁移引入通用路由/全局状态框架。组件内部状态与少量共享范围状态足够。
- 前端源文件放在独立目录，产物嵌入现有 Go Web 包。构建使用锁文件和固定依赖解析，`make build`、检查流程与发布流程明确执行前端构建后再编译 Go。
- 产物不作为手工维护源码。构建后的资源用受限的嵌入资源表服务，不新增任意文件读取或目录浏览。开发依赖和 source map 不进入发行资源。
- 现有 Go API 继续负责认证和输入输出安全；React 以文本/安全组件渲染台账字符串，禁止把资产描述当 HTML、指令或授权。
- 沿用安全整数保护与原始数值文本处理，不让历史游标、记录数字因迁移被静默取整。
- 保留 AbortController、请求序号、会话失败清空和完整错误状态。客户端显式刷新范围，不做后台采集或自动重试写入。

先在正式 CSP 下验证实际需要的 Radix 组件，尤其菜单、Select、Dialog、Portal、暗色主题和内联定位行为。保持脚本仅同源、无 eval 和无外部资源依赖；样式兼容优先使用外部样式、静态主题类及可用原生控件，不加入通用 `unsafe-inline`。若必要组件确实需要策略调整，必须说明具体机制与最小改动，回到设计评审；不能在实施中悄悄扩大策略。

参考：[Radix Themes 样式](https://www.radix-ui.com/themes/docs/overview/styling)、[主题](https://www.radix-ui.com/themes/docs/components/theme)、[Vite 静态构建](https://vite.dev/guide/build.html)。具体版本在实施计划前核对并锁定。

## 验收要求

1. C 三栏主流程可用：筛选 → 发现风险/未知 → 连续选择资产 → 查看完整结论、依据与关系；窄屏可返回列表。
2. 资产摘要与共享单资产 inspect 在相同输入下逐项一致；覆盖风险与未知并存、无配置/不支持、全部 NA、豁免、归档、共享实例失败、过期证据及不同账号身份。
3. 首屏摘要不产生按资产数量增长的浏览器请求；取消/超时/超限/台账损坏不能返回部分成功或保留旧绿状态。
4. 配对、两设备会话、退出/撤销、CSRF/来源、CSP、秘密过滤和安全整数保护不回退。
5. 巡检与变更原有语义、编辑审阅、陈旧预览拒绝、失败恢复、云回执 uncertain 和只读文件不变检查全部保留。
6. 核对亮/暗色、焦点与键盘、Mac Safari/Chromium，以及窄屏。没有执行的浏览器/辅助技术检查须明确标注。
7. 从干净源码构建并运行打包后的二进制，断开外部资源加载仍可打开三页；运行端不需要 Node。

实现时补行为测试和必要的浏览器回归；不以截图代替契约验证，也不为纯样式细节大量增加脆弱测试。文档草案阶段不运行业务测试或修改应用。
