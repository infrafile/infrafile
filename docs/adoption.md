# 使用方范围与旧流程承接

迁移前先在使用方的唯一权威仓库登记本页清单，版本和真实证据留在该私有仓库。工具仓只保存通用约束和虚构示例。范围清单是迁移契约；进度继续由使用方现有行动项与本项目任务 issue 维护。

## 最少需要记录什么

| 项目 | 必填内容 |
| --- | --- |
| 权威与版本 | 原仓库、源 commit、未提交差异；输入文件及 SHA-256；映射工具和目标二进制版本 |
| 资产范围 | 六种记录的选取条件、live/archived、排除理由、旧键到新键及跨范围引用 |
| 能力范围 | 插件/实例/服务/字段/动作，分别声明登记、观测、比较、计划、执行、回读；引用 `capabilities` 的限制 |
| 调用者 | 旧命令、脚本、调度、CI、MCP 客户端、SSH 配置、通知与控制入口；每项保留/替换/暂缓的决定 |
| 责任与证据 | 实施负责人、范围/切换确认人、验收证据位置与等级；未知负责人显式待确认 |
| 切换与恢复 | 切换前置门槛、唯一编辑入口、旧读取器兼容方式、完整恢复点、后续人工修改的保护与停止条件 |

未映射字段逐项归入转换、继续由旧流程负责、修复或有期限例外。`x-` 扩展保留原值有助于防止丢失，但不证明新工具理解其语义。字段数/记录数相同、Schema 通过或临时投影可读均不表示迁移完成。

## 虚构清单示例

下面的路径、实例和责任角色仅为示例，命令是否存在以使用方实际仓库为准。

| 旧能力与来源 | v1.0 决定 | 责任与验收 | 切换和恢复 |
| --- | --- | --- | --- |
| 六类 YAML、归档与外键 | 声明全量候选范围；源 YAML 在切换前继续唯一编辑 | 实施 Agent / 使用方负责人；逐字段和关系对账、两次生成一致 | T06 映射与旧读取器适配、T13 事务、T19 恢复通过后，才按批准范围切换 |
| `servers.yaml` → SSH 配置 | 保留旧渲染器和可信主机配置 | SSH 使用者；别名、跳板、IdentityFile、额外选项逐项比较 | 不直接覆盖用户 SSH 配置；未表达的选项继续保留 |
| `cloud-a` 的 CDN 采集 | 接入声明的只读实例/服务；新建成功回执和正向基线 | 实施 Agent；显式 doctor、sync、inspect；403/空结果/过期单列 | 不把旧快照改时间或归一化状态当原生 API 结果；失败恢复旧调用者 |
| fleet、DNS 与应用探针 | 现有判据继续运行；固定 SSH uname 不能代替应用检查 | 运维负责人；执行/检查/组件覆盖分别验收 | 不删除旧判据来消除 unknown；未支持项保持旧证据入口 |
| 原有调度、变化通知、独立心跳 | 保留原 scheduler/通知；T10 接入新报告与历史 | 运维负责人；实际触发、漏跑、变化、收件确认分开记录 | 不再建一套调度或通知平台；失败保留待确认通知 |
| 证书签发/部署/续期、备份/恢复 | 保留专用工具和原运行手册 | 原负责人；TLS 不代替签发清单，校验和不代替恢复 | 不属于 v1.0 新增控制器；不停止旧任务 |
| 云写、DNS 发布、远端运维 MCP | 保留既有授权入口；infrafile MCP 只读/计划 | 操作者与授权人；专用测试范围、审阅摘要、回读、恢复 | 不从台账文字取得授权；zone 暂停不等于单域名暂停 |

每个被替换调用者必须能指向新入口和证据；每个保留调用者必须能指向现行入口及负责人。不要在工具仓公开账号、IP、真实快照、密文或本机配置。

## 分范围切换门槛

1. 固定源文件哈希并确认未提交修改；源变化即重新生成和重验受影响映射，不继续使用旧候选。
2. 逐字段处理意图、观测、豁免、归档与外键；缺日期/ID 不补造，observed 不反写 desired。
3. 在隔离副本完成重复生成、候选编辑、旧调用者兼容和完整恢复；恢复不能覆盖当前仓库或切换后合法修改。
4. 权威仓库保持一个；投影只由源生成，禁止双向独立编辑。若旧调用者不能消费目标格式，先适配或保留该范围，不删除旧功能凑成切换。
5. 按适用授权启用唯一编辑入口，T18 留下实际切换和持续运行证据。仅范围设计完成时，不宣称已迁移或上线。
