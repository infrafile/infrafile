# 兼容、存储版本与恢复

本文冻结 T02 的版本边界、管理记录外层和新命令退出码。现有字段继续由 [JSON 契约](json/README.md)、[插件协议](plugins.md)及内嵌 Schema 约束。问题身份/载荷、编辑事务和云执行记录分别在 T08/T09、T13、T15 实现；本文不表示这些功能已经可用。

## 公共接口与版本

| 接口 | 版本及兼容规则 |
| --- | --- |
| inventory / Config | 保留 `apiVersion: infrafile/v1alpha1`、六种记录和既有字段含义。新字段显式使用，不批量改写旧数据；严格旧读取器可能拒绝新增字段 |
| 观测与同步证据 | Snapshot、Sync、SyncStatus、Presence 的 v1alpha1 信封、文件名和含义不变；缺失元数据不补成成功 |
| CLI JSON | 顶层 `version: v1`；允许新增字段/命令，不删除、改名或改变冻结字段/退出码；消费者忽略未知结果字段 |
| MCP | SDK 协商传输版本；保留七个既有工具的名称、参数、annotations 和结果含义。capabilities 为新增工具，Schema bundle 可有新增定义；参数仍拒绝未知字段和重复键 |
| 插件 | 保留 describe `protocol_version: v1`、方法名、JSON-RPC 与 Snapshot 信封。能力目录不扩展旧 describe；未声明的细节为 unknown |
| 云计划 | 保留 `version: v1` 单动作文件。拒绝目标符号链接、目录和设备。T15 的新前提若旧格式无法表达，须使用新计划版本，不改变旧字段含义 |
| 管理记录 | 独立 JSON 信封 `version: v1`，须先显式启用 `storageVersion: v1`；未知版本/种类/外层字段拒绝，不猜测或自动转换 |

`v1alpha1` 不表示可以任意破坏字段；破坏性变更使用新版本并提供显式迁移。Schema 校验只证明形状，不能代替大小、重复键、权限、敏感字段和业务语义校验。

## 显式存储升级

旧仓保持现状：init、查询、sync 和安装新版都不自动加入存储标记。准备启用新管理记录时，先审阅并显式设置：

```yaml
apiVersion: infrafile/v1alpha1
kind: Config
storageVersion: v1
```

这是最低存储能力标记，不表示迁移或业务验收成功。v0.3.0 不识别该字段：validate 返回 1 并报告 Schema 问题；依赖完整校验的 show / audit / sync 等业务操作在开始前返回 2。version、help、Schema 等独立入口仍可用。重复标记或未知值在新版也无效。

后续管理记录写入器必须先核对标记，未启用时拒绝，不能先写记录再补标记。分步保存时标记先落盘，中途失败宁可让旧版拒绝。配置变更会改变配置哈希，相关同步证据和正向基线须重新建立，禁止改旧回执哈希来伪造连续性。

旧读取器可能跳过隐藏文件，所以仅隐藏新增文件不足以安全降级；该标记依赖原有业务校验，不隔离同一 OS 用户或外部脚本。当前没有新管理记录的生产写入器或自动升级/降级命令。

## 管理记录信封与布局

`protocol/record.schema.json` 冻结 version、kind、data 三项外层字段：

```json
{"version":"v1","kind":"FindingHistory","data":{}}
```

示例只展示信封，空 data 不是有效业务历史。完整载荷 Schema、迁移和状态转换由对应任务冻结；未经这些校验不能发布、接受或据此恢复业务记录。未知外层字段须拒绝，转换保留原文件并使用明确版本。

| kind | 固定位置 | 载荷责任 |
| --- | --- | --- |
| FindingHistory | `state/.findings.json` | T08/T09：身份算法版本、固定输入哈希、检查时间、问题和变化；锁内评估后原子替换单文件 |
| EditTransaction | `.infrafile/transactions/<id>.json` | T13：仓库/HEAD/内容基准、本次文件与前后哈希、备份定位、阶段和恢复状态 |
| ExecutionReceipt | `history/executions/<id>.json` | T15：计划摘要、主体说明、目标/范围、前提核对、写前/写后及回读结果；uncertain 不冒充成功 |

id 为 64 位小写十六进制，不从用户路径直接拼接。每文件最多 4 MiB，同时遵循共享解析器的 100 层、100,000 展开节点和 16 MiB 展开预算；扩大须有实测和故障测试。读取拒绝重复键、多文档、未知版本、未知外层字段、符号链接、非普通文件及越界路径；损坏的活动事务阻止相应写入，缺历史不表示问题恢复。

`.infrafile/` 保存本机恢复材料、会话和锁，后续创建入口须配置忽略，不默认提交 Git；会话秘密永不纳入历史。最终脱敏回执由使用方选择是否纳入 Git。历史可能含私有资产信息，公开仓库仅存虚构夹具，任何记录都不保存凭据值。

T09/T13/T15 实现锁、原子替换、写前记录和恢复，不能用信封 Schema 代替事务保证。活动问题不得被容量上限裁掉；清理前导出、容量和保留期由 T09 实测冻结，当前不承诺默认数值。

## 新命令退出码

capabilities 和 doctor 已实现，下表其余为待实现接口。audit 的原 ok 和 0/1/2 语义保持不变，unknown notice 不表示已证明无风险。

| 命令 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| capabilities | 返回目录 | 不使用 | 用法/输出失败 |
| doctor | 请求的检查均完成并通过 | 检查失败或请求项无法确认 | 参数错误或无法开始 |
| inspect | 成功生成执行/覆盖/风险报告，可包含风险及 unknown；不等于全通过 | 不使用 | 参数错误或无法读取报告所需数据 |
| findings refresh | 推进成功或相同输入无变化，可仍有活动问题 | 不使用 | 参数/读取/冲突/保存失败；保留旧历史 |
| change preview | 候选有效，返回 diff | 候选业务校验未通过 | 参数错误或无法读取候选/仓库 |
| change apply | 本次提交完成或无变化 | 前提拒绝，或进入事务后需恢复；区分 rejected / recovery_required | 参数错误或无法开始，未写业务文件 |
| serve | 正常退出 | 不使用 | 用法/启动失败；HTTP 错误不作为进程退出码 |

新结果带 `version: v1`。进入事务后失败须给出恢复定位，不输出成功、不自动 reset/盲重试/覆盖用户修改。run 和已有 apply 沿用现有退出码。未来载荷字段随各实现任务审查冻结，不把本任务的命名设计当作已实现 API。

## 程序回退与数据恢复

1. 首次启用前检查 Git 状态，保留 inventory、Config、state、未提交内容及密文的完整恢复点，密钥另行加密备份。Git 提交不包含被忽略或未跟踪文件，不能独自充当完整备份；真实路径及秘密只留使用方私有记录。
2. 旧二进制不能直接接管带标记的数据仓。不存在只移除标记的降级流程，不得丢弃历史/活动事务来通过校验。
3. 首先在**新目录**恢复升级前完整副本及相对密文布局，现仓保持不动；核对旧二进制版本、校验、查询和离线审计。不得改时间制造新鲜证据。
4. 升级后合法人工修改逐项比较，在旧版可表达时审阅转录；不能用旧备份覆盖现仓。无法表达时保留新程序处理。兼容导出尚未实现，不提供虚构命令。
5. 活动事务损坏或当前哈希不符时停止对应写入，保留证据；T13/T15 的恢复只处理仍属于本事务的内容。正式候选的升级/回退/故障恢复由 T19 验收。

## 重放与证据

显式提供旧正式二进制，测试不下载/安装、不访问真实台账或云账号：

```sh
INFRAFILE_PREVIOUS_BINARY=/absolute/path/to/v0.3.0/infrafile \
  go test ./cmd/infrafile -run '^TestV030Compatibility$' -count=1 -v
```

覆盖旧版产生的虚构快照、CLI 查询/审计退出码、两个实际 stdio 子进程的七个旧工具、v1 计划及坏版本/重复键/超限、存储标记对旧业务操作的拒绝，以及恢复完整旧配置后的可读性。仅排除 audit 本次 as_of 时钟差异和 Schema bundle 新增的 storageVersion 定义，不忽略业务字段。plan 工具使用不存在目标的安全拒绝路径，成功云计划由控制回放覆盖；没有真实云写。

未提供旧二进制时专项测试明确 skip，普通 CI 不能替代这项证据。原生平台及版本随实现 PR 记录；T19 仍须对正式候选完成升级/恢复，T02 离线重放不替代该门槛。
