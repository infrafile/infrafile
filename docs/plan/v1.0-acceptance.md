# v1.0 验收与发布门槛

**状态（2026-10-28）**：验收设计，所有条目尚未作为 v1.0 验收完成。对应[完整方案](v1.0.md)和[任务拆分](v1.0-tasks.md)。每个 AT 与同号 T 对应；完成状态和证据链接维护在工作包 issue。

## 证据要求

每条记录至少包含：任务/验收编号、代码或二进制版本、数据/配置版本或哈希、执行环境、开始/结束时间、输入范围、预期、实际结果、退出码/工具结果、证据位置、限制及负责人。真实写入另附授权范围、计划摘要、前后回读和恢复记录。

证据分层独立标记：离线夹具、真实只读、真实写入、持续运行、实际客户端、独立外部试用、发布产物。低一层不能替代高一层。公共仓库/issue 仅存虚构数据或脱敏结论；真实资产、原始日志和秘密留在使用方私有环境。不得把旧快照改时间制造新鲜证据。

## 三条端到端验收路径

### 自有台账

1. 依据 T03 选定资产、检查和旧流程范围，记录基准、未承接项与唯一权威入口。
2. 在隔离副本执行映射、校验、重复运行和恢复，复核账号/实例/自然身份/引用，旧数据不可被投影反向覆盖。
3. 按明确范围上线只读采集和检查，执行与覆盖分别记录；开始累计 14 个日历日证据，至少包含两次每周完整采集。
4. 覆盖成功、首次失败、失败保旧、恢复、漏跑和证据过期；缺少自然发生样本时仅在专用实例或隔离副本注入故障。保存独立漏跑观察证据。
5. 复核迁移缺口、unknown、403 等仍未解决项，明确修复/不支持/有期限例外。无法满足已承诺范围的缺口阻断该范围切换，不能用豁免改写事实。
6. 在获授权范围执行正式接入/分范围切换，确认旧流程承接、密文引用与恢复路径，记录切换后验证。其余范围继续原流程。

通过条件：每个应运行项都能追溯到成功、失败或漏跑；漏跑在配置的下一观察周期与宽限内被发现；相同问题不重复、失败不误恢复；声明范围内每种检查都有结论和证据，不要求把真实业务风险全部消除后才能发布工具。

### 外部独立上手

首轮使用干净 Linux amd64、正式候选归档、env 凭据与真实 Cloudflare zone/DNS 范围；补充 SOPS/age 和 macOS arm64 安装/恢复。先只读发现/纳管，再使用专用无业务流量 zone 验证受控动作。所需账号/权限由试用者自行准备，私密值不交给维护者。

步骤：安装/验签 → init → 配置引用 → 离线/在线 doctor → sync → 审阅草稿 → 纳管/watch → inspect/历史 → Web 登录和查询 → MCP 客户端发现 → 获授权的单动作流程 → 重复采集/重启 → 升级/恢复。

测试者不能依赖维护者私人脚本或口头补配置。发生求助要保留原因，并在修正文档/产品后重验受影响步骤。记录耗时用于发现摩擦，不虚构“十分钟接入”的硬指标。无人独立完成时 AT17 保持未完成。

### Agent 受控操作

先走无云写的台账编辑流程：读取能力/关系 → 给出带证据的修改建议 → 预览 → 按授权提交 → 重新查询与校验。再对专用 zone 走 plan → 展示目标/作用范围/摘要 → 确认适用授权 → CLI apply → 配置回读与独立入口检查 → 新计划恢复原状态。

还须用离线夹具覆盖计划过期、摘要变化、配置漂移、远端漂移、写前记录失败、写后进程中断、回读 mismatch/uncertain。失败不能通过不加约束地重试来“验收通过”。真实受控写缺权限/测试目标/授权时保持未完成；不拿真实业务 zone 暂停来制造测试样本。

本版证明受信任本地 Agent 能按授权流程完成工作，不证明它在拿到同一 OS 用户权限后无法绕过 CLI。MCP 只读边界、摘要一致性和授权主体认证必须分别表述。

## RC 准入与正式发布门槛

RC 产物先于最终使用验收：待验功能具备、相关自动化检查通过、候选接口和已知限制明确后，T20 即可生成绑定 commit 的候选归档，交给 T17/T19 使用。RC 不宣称三条真实路径已通过；候选代码变化后重验受影响场景。以下条件用于正式发布，不能反过来阻止生成验收所需的 RC。

- 三条端到端路径都有完整证据，AT01–AT19 逐项有结论；条件能力的例外不能豁免三条核心路径。
- 无未解决的数据丢失、凭据泄露、误恢复、超出授权范围执行或静默覆盖用户工作的问题。
- 冻结数据/CLI JSON/MCP/插件公共接口清单、能力/平台支持矩阵、升级与恢复步骤。v1alpha1 命名可保留，但冻结字段的兼容承诺必须明确。
- 最终实现提交运行项目完整检查和 CI；文档修订不重复业务验证，除非改变契约/验收输入。真实集成与发布检查不能用 CI 替代。
- 按[发布指南](../release.md)为本次版本核对 tag、commit、签名、校验和、归档、Homebrew、安装/升级和离线上手。不得沿用旧版本完成记录当作新证据。
- 公开已知限制：非原生验证的平台、条件云权限/字段、未提供的执行能力、本地信任边界及需要恢复数据后才能降级的情况。

AT20 成功后才关闭 v1.0 总任务。代码合并、计划文件齐全、只读测试通过或长时间没有报警，都不能单独构成发布验收。
