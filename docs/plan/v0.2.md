# v0.2 实现计划

**状态（2026-10-28）**：M0–M6 的功能与本地验收已完成。M0/M1 已在 origin/main（最新 `4ab0153`）；M2–M6 接续隔离工作区的既有开发，统一在 `codex/v0.2-audit-gatus` 交付。M7 的文档与离线上手流程已补齐，正式发布、签名产物及 Homebrew 安装验收待完成；尚未发布 v0.2.0。

> 范围以 [设计](../design.md) 的 v0.2 一行为准：审计与 drift 检测、waivers 偏差豁免、生成 Gatus 监控配置。本计划只排顺序、定完成标准和落实细节，不扩大范围。

## 产品主线

v0.1 解决「把资产记下来」，v0.2 解决「记下来的还对不对」。用户闭环：

**定时 `sync` → 快照提交进 git → `audit` 在 CI 或 agent 里跑 → 修台账，或写豁免并注明理由**

`audit` 离线、不解析凭据，CI 里不需要任何密钥。各里程碑和快速上手文档都围绕这条闭环。

## 原则

沿用 [v0.1 计划](v0.1.md) 的原则，另加三条：

- **审计只读、离线**：`audit` 只读 `inventory/` 和 `state/`，不访问网络、不解析凭据。要拿到新的观测结果，先跑 `sync`。
- **自然身份匹配**：台账记录和观测条目按域名、`provider` + `resource_id`、地址这类自然身份对应，不按主键对应。`import state` 生成的主键带哈希，人也可能改过名。
- **规则少而准**：每条规则都要有误报夹具和漏报夹具。宁可漏报，不刷屏。

## 实现决定

| 事项 | 建议 | 理由 |
|---|---|---|
| 命令 | `infrafile audit [目录] [--rule <id>]... [--json]` | 与 `validate`、`expiry` 同形；`--rule` 可重复，用来只跑部分规则 |
| 退出码 | 0 无未豁免发现；1 有未豁免发现；2 用法错误、台账校验未通过或 `state/` 无法读取 | 与 v0.1 一致：区分「有问题」和「没跑起来」 |
| 规则 ID | 小写下划线，如 `origin_exposure`；发布后不改名 | waivers 按 ID 引用，改名会让豁免静默失效 |
| 发现的结构 | `rule`、`target`（M2 为 `plugin/instance`，后续规则可用 `Kind/name` 或自然身份）、`file`、`message`、`evidence`（只含观测到的非敏感字段）、`waiver`（命中的豁免，或 null） | 采用已有实现的 `waiver` 字段；被豁免的发现照样输出，只是不计入退出码 |
| 观测时效 | 默认不限，`--max-age 7d` 时把超期实例作为 `stale_state` 发现报出；每条发现的 `evidence` 都带所依据快照的 `observed_at` | 离线审计依赖 `state/_sync.yaml`，过旧的快照可能产生误判；不加 `--max-age` 时至少让人看得到快照有多旧 |
| waivers 位置 | `metadata.waivers: [{rule, reason, until?}]`，按设计稿 | 随记录删除而消失，不留孤儿 |
| 规则 ID 清单 | 在 M1 就定下 v0.2 发布的全部规则 ID（常量表，`validate` 和 `audit` 共用），后续里程碑只实现、不新增 | 豁免校验要认识规则 ID；若规则晚于豁免出现，先写的豁免会被判成「未知规则」 |
| 豁免校验 | `validate` 检查 `rule` 是已知规则 ID、`reason` 非空、`until` 是日期；过期豁免不报 validate 错误，由 `audit` 视为无效并输出 `waiver_expired` 提示 | 过期是时间推移造成的，不应让原本通过的台账突然校验失败 |
| 观测条目的豁免 | `stale_state` 保留 M2 的 `audit.ignore: [{rule, plugin, instance, reason, until?}]`，按整个实例匹配；M3 的 orphan/zombie 必须增加完整自然身份 `match` | 不为了豁免而新建台账记录，生命周期豁免不压住同实例的其他资产 |
| 快照范围 | 只读 `infrafile.yaml` 里当前启用的插件实例的快照；其余快照（实例已删除或停用）不参与规则，只在输出里提示 | 删掉实例后旧快照仍在 `state/`，若参与比对会持续产生孤儿、僵尸误报 |
| 无同步记录 | 快照存在但 `_sync.yaml` 里没有该实例时，`observed_at` 记为未知；带 `--max-age` 时按超期报 `stale_state` | 手工放入或旧版本留下的快照没有同步时间，不能当成新鲜的 |
| 豁免未命中 | 有效豁免（含 `audit.ignore`）一条发现都没压住时，输出「豁免未命中」提示，不计入退出码 | 问题修好后豁免容易被遗忘，越积越多 |
| Gatus 版本 | 以 Gatus v5.37.0（2026-09-24）为准，只用其文档化的 `endpoints[]` 字段 | 已核对官方 README；渲染结果不依赖 Gatus 内部行为 |
| 依赖 | 不新增模块 | 规则和渲染都是对已有数据的计算 |

### 生命周期规则的定义

| 规则 | 建议定义 |
|---|---|
| `orphan` | 最新快照里观测到，台账里没有对应记录（含归档记录）。提示用 `import state` 补录 |
| `zombie` | 台账里已归档，但最新快照里仍观测到在用 |
| `missing` | 台账里在用，记录绑定了某个已启用的插件实例（如 `spec.control` 或 `provider` 与实例对应），但该实例最近一次成功快照里没有它。推到 v0.3，原因见「现状核对」第 1、2 点 |

对应关系复用 `import state` 的映射：注册域名和 WHOIS 对应 Domain，CDN 和 Cloudflare zone 对应 Resource，SSH 实测对应 Server；DNS 和 TLS 观测不参与生命周期规则。

例外：Cloudflare zone 除了匹配 `type: dns-zone` 的 Resource，同名的 Domain 也算覆盖。否则 DNS 托管在 Cloudflare、但没为 zone 单独建 Resource 的每个域名都会报孤儿。

## 现状核对（2026-10-26）

动工前对照代码核实了计划依赖的几点，结论影响 M2–M6：

1. **同步失败不留痕**：`state/_sync.yaml` 只记录每个实例最近一次**成功**同步的时间；同步失败时不写快照、不改时间，旧快照原样保留。所以离线审计分辨不出「上次同步失败」，原 M3 的「同步失败的实例跳过 `missing`」做不到，只能看快照有多旧。
2. **`missing` 有结构性误报**：台账里新加的记录，在下一次 `sync` 之前必然「快照里没有」。离线审计拿不到记录的创建时间（除非读 git 历史），无法区分「刚录入」和「真的不在了」。
3. **自然身份**（与 `import state` 的映射一致）：
   - Domain：`metadata.name` 与观测到的域名比对，统一小写、去掉末尾的点；
   - Resource：`provider` + `resource_id`；观测里没有 ID 时（百度云 CDN 不返回 ID）退回 `provider` + `type` + `endpoint`；
   - Server：`spec.address` 与 SSH 快照的 `host` 比对。
4. **CDN 状态已有、回源没有**：阿里云、腾讯云、天翼云的 CDN 快照已含 `status`（各家原始取值，口径不一），百度云没有；四家都没采集回源配置。
5. **Gatus**：v5.37.0（2026-09-24）仍是最新版本（2026-10-26 经 GitHub API 核对）。
6. **`examples/homelab` 的数据撑不起审计演示**：
   - `state/` 下没有 `_sync.yaml`，`stale_state` 无从演示；
   - `infrafile.yaml` 只配了 `example`、`example-python`，`state/` 里却是 aliyun、cloudflare、dns、ssh 的快照，按「快照范围」的决定全都不参与；
   - `example.net` 的 `origin_exposure` 豁免找不到证据：Cloudflare 快照里 `dns_records: []`，也没有 `example.net` 的 DNS 探测快照；
   - web1 的 `address` 是 `203.0.113.10`，`example.com` 的 `@` 记录和 `dns/blog.yaml` 却是 `192.0.2.10`，对不上。

## 里程碑

### M0 v0.1.1 修复（已完成）

在 v0.1 线上修复审查中确认的问题，原计划单独发 v0.1.1：

1. WHOIS：注册域名的响应里只要任意位置出现 `not found` 等字样（如注册人名称），就会被判成 `found:false`，`import state` 随之跳过。改为只看行首的「未找到」标记，并以响应里存在匹配查询域名的 `Domain Name` 行为准。
2. `run`：子进程以非零码退出、后台子孙进程仍占着 stdout 时，返回子进程的退出码而不是 2，晚到的输出被静默丢弃。先判断 `exec.ErrWaitDelay`。
3. 明文扫描不检查映射的键：`spec.x-notes: {<token>: backup}` 能通过校验。
4. DNSControl：单标签目标（如 CNAME `web`）能通过校验，生成 `"web."`。在 schema 或生成器中要求至少两个标签。
5. DNSControl：等价 AAAA 地址的不同写法（大小写、零压缩）不算重复，违反契约里「重复记录退出 2」的约定。用 `net/netip` 规范化后再比对。
6. 一并处理此前记录的低风险项：SOPS / op 引用允许空格；引用正则和 `op.go` 对控制字符的判断不一致；`sameJSON` 拒绝显式的空 `ruleset_id` / `rule_id`；`apply` 判断 stale 用了类型断言，没有用 `errors.As`。
7. inventory 下的 YAML 可以是指向仓外文件的符号链接，目前会被加载，文档里没有写。已改为拒绝（报 `layout` 问题），与 SOPS、导入和插件的符号链接边界一致；kind 目录本身是符号链接时同样拒绝。

**完成标准**：每项都有先失败、后通过的回归测试；`make check` 通过；v0.1.1 按[发布指南](../release.md)发布。

**结果**：7 项及 kind 目录符号链接均已修复，各带回归测试，`make check` 通过，13 个提交（`a24a6d8`…`7863f91`）已推送 origin/main。尚未打 `v0.1.1` 标签。

遗留（低风险；第一条已列入「推到 v0.3」）：

- `inventory/` 目录本身、`infrafile.yaml` 本身是符号链接时仍会被跟随。
- schema 导出里凭据引用的 `\p{Cc}\p{Z}` 写法未核实编辑器端（VS Code YAML 插件等）的正则兼容性；不兼容时只影响编辑器提示，`validate` 用的是 Go 端正则。
- `op://` 名称允许空格是有意为之，不改。

### M4 源站暴露 `origin_exposure`（本地验收完成）

- 判断对象：`Domain.spec.bindings` 中写了 `server` 的主机名（含根域名 `@`）。只写 `app` 的绑定本版不展开到 App 的部署，文档写明。
- 证据来源：
  - 台账自身：`Domain.spec.dns.records` 里该主机名的 A / AAAA 记录不是 `proxied: true`，且 `content` 等于该 Server 的 `address`。纯离线，不需要 `sync`，`apply` 之前就能拦下；
  - Cloudflare 快照里该主机名的 A / AAAA 记录，`proxied: false`，且 `content` 等于该 Server 的 `address`；
  - DNS 探测快照里该主机名解析到该 Server 的 `address`。
- 地址比对用 `net/netip` 规范化，与 DNSControl 判重一致。
- 只比对台账里写明的 Server 地址，不做反查或端口扫描。
- 绑定的是 Resource（CDN）时不报；地址是私有、回环或链路本地地址时不报（`netip` 的 `IsPrivate`、`IsLoopback`、`IsLinkLocalUnicast`）。文档网段（192.0.2.0/24 等）不算私有，示例才能演示。
- 先对齐 `examples/homelab`（「现状核对」第 6 点）：让 `example.net` 有一条能命中的证据，使已有的豁免真正压下一条发现；统一 web1 与 `example.com` 记录的地址。

**完成标准**：代理开启、经 CDN、私有地址三种不报的夹具，以及台账未代理、快照未代理、直接解析三种要报的夹具都通过；豁免能压下发现；homelab 的 `example.net` 豁免不再报「豁免未命中」。

**结果（2026-10-28）**：完成三种证据来源、IPv4/IPv6 规范化、地址与绑定边界、重复证据去重及豁免隔离；示例中的地址已统一，example.net 的豁免实际命中。补齐 CLI/MCP 黄金输出、JSON 契约与 Agent 指南。全仓 make check 通过，未做真实 DNS、云端或端口探测。

### M5 生成 Gatus 配置（本地验收完成）

不依赖 audit，可以与 M3、M4 并行；排在 `cdn_drift` 之前，保证它不被可砍项拖住。

- `infrafile gatus [目录] [--json]`：从台账单向渲染 Gatus `endpoints` 片段，输出到 stdout，不写文件，不读 `state/`。
- 输入：在 `Domain.spec.bindings[]` 增加可选的 `monitor`（`path`、`interval`、`status`），只为写了 `monitor` 的绑定生成端点，避免把所有子域名都推进监控。
- 渲染规则：
  - `name` 用 `<绑定名>.<域名>`，`group` 用 Domain 主键，`url` 为 `https://<主机名><path>`；
  - 条件为 `[STATUS] == <status>` 加 `[CERTIFICATE_EXPIRATION] > 240h`；
  - 不加 `[DOMAIN_EXPIRATION]`：域名到期已由 `infrafile expiry` 按台账检查，Gatus 再走 whois 是重复检查，且 whois 不稳定、对部分后缀支持存疑。
- 不输出 `alerting`、`storage` 等部分，也不写任何凭据：用户把生成的文件放进 `GATUS_CONFIG_PATH` 指向的目录，Gatus 会合并目录下的全部 YAML，告警配置留在用户自己的文件里。
- 归档的 Domain、Server 不生成端点；输出排序稳定，重复生成结果一致。

**完成标准**：黄金测试锁定文本和 `--json` 输出；用 Gatus v5.37.0 加载生成的配置验收一次（只验证配置能加载，不做真实探测），并记录验收方式。

**结果（2026-10-28）**：实现显式 monitor schema、gatus CLI 与 JSON 契约；默认 /、1m、200，只输出 HTTPS endpoints 和状态/证书条件。测试覆盖默认值、自定义路径与查询参数、稳定排序、重复端点、非法路径/间隔/状态码、归档边界及空输出。在仓外临时模块调用 Gatus v5.37.0 的 config.LoadConfiguration，成功加载生成的一个端点，未启动探测；[验收方式](../json/gatus.md#配置加载验收)。未给 infrafile 增加依赖。

### M6 CDN 配置漂移 `cdn_drift`（本地验收完成）

按「现状核对」第 4 点拆成两部分：

**v0.2 做：停用漂移。** 不需要新采集。

- 台账里在用的 CDN Resource，快照里对应条目的 `status` 表示已停用或已下线时报 `cdn_drift`。
- 各家 `status` 取值要按官方文档逐一核实后写成映射表；映射表里没有的取值不报，并在 `evidence` 里给出原始值。
- 百度云快照没有 `status`，本版不判断。
- 砍线：哪家的取值无法从官方文档核实，就不判断那家；三家都核实不了，发版前把 `cdn_drift` 从 `waivers[].rule` 枚举和规则注册表中删除，整条规则与回源漂移一起推到 v0.3。v0.2 尚未发布，删除不算破坏兼容。

**推到 v0.3：回源漂移。**

- 需要新增台账字段（如 `spec.origin`），并为四家国内云及 Cloudflare Origin Rule 补充采集回源配置。
- 每家都要按官方文档核实接口、分页、限流和最小权限，工作量明显大于本版其他各项。

**完成标准**：已核实的各家离线夹具覆盖在用、已停用、未知取值三种情况；未知取值不产生发现。

**结果（2026-10-28）**：三家官方状态均已核实，无需裁剪：阿里云/腾讯云仅 offline 报偏差，天翼云仅 6/8；百度云不判断。复用自然身份匹配，在用 CDN Resource 才参与，支持记录级 waiver，保留原始状态、区域、观测时间。未知/缺失状态不产生发现，原始值进入 cdn_status_unknown 提示。离线测试覆盖三家在用/停用/未知/过渡状态、身份与归档隔离、去重、豁免、损坏输入、取消和 MCP/CLI 一致性；全仓 make check 通过。[官方来源和映射](../json/audit.md#cdn-停用漂移)。
