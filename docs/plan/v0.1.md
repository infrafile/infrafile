# v0.1 实现计划

**状态**：已确认（2026-10-24）。M0、M1、M2、M3、M4、M5、M6、M7、M8 已完成。

> 范围以 [设计](../design.md) 的 v0.1 一行为准。本计划只排顺序、定完成标准和落实细节，不扩大范围。

## 原则

- **每个里程碑结束时都能用、都能发版**。不做铺一大片、最后才拼起来的开发方式。
- **`--json` 从 M1 起每个命令都带**，不留到最后补。输出结构登记在 `docs/json/` 里，由黄金测试锁定。
- **`examples/homelab` 跟着功能一起长**：每加一个能力，示例台账就补上对应数据，黄金测试随之更新。
- 依赖从严：只在下文点名的地方引入第三方库。

## 实现决定

以下是设计稿留到实现阶段再定的事项，已于 2026-10-24 确认。

| 事项 | 决定 | 理由 |
|---|---|---|
| Go module 路径 | `github.com/infrafile/infrafile` | 已定：仓库放在 GitHub org `infrafile` 下 |
| `apiVersion` | `infrafile/v1alpha1` | 不依赖还没注册的域名；1.0 之前都留在 alpha |
| 数据仓目录结构 | 见下方「数据仓布局」 | |
| 归档的表示 | 记录留在原路径，加 `metadata.archived: {date, reason}` | 文件不挪位置，`git log` 不断链；live 记录引用已归档记录时视为外键错误 |
| 防删除 | `infrafile validate --base <git-ref>`：对比基线，发现删除的记录就报错 | 「下线不删除」靠校验落实，可以接进 pre-commit 和 CI |
| 自定义字段 | `spec` 顶层允许 `x-` 前缀的键，不校验内容；其余未知字段一律报错 | 拼写错误能被拦下，个人习惯的字段也有地方放 |
| 退出码 | 0 通过；1 发现问题；2 用法错误或命令无法执行（不是数据仓、读不到 git 基线等） | 脚本能区分「台账有问题」和「命令没跑起来」 |
| 计划文件格式 | JSON；带格式版本、生成时间、动作列表，每个动作记录目标和生成时观测状态的哈希；`plan show` 负责人类可读的渲染 | 机器读写稳定；哈希用于 apply 前的 TOCTOU 比对 |
| `state/` 快照 | `state/<插件>/<实例>.yaml`，套同样的信封（`kind: Snapshot`）；**快照文件里不写时间戳**，同步时间集中记在 `state/_sync.yaml` | 时间戳每次都变，混进快照会让 `git diff` 满屏噪音，看不出实质变化 |
| CLI 框架 | `github.com/spf13/cobra` | 子命令多，自带补全和帮助 |
| YAML | `go.yaml.in/yaml/v3` | 原 `gopkg.in/yaml.v3` 已归档，这是官方接手的维护版；v4 还在 rc |
| JSON Schema 校验 | `github.com/santhosh-tekuri/jsonschema/v6` | 纯 Go，支持 2020-12 |
| sops / age | `github.com/getsops/sops/v3/decrypt`、`filippo.io/age` | 设计已定以库的方式链接 |
| MCP | `github.com/modelcontextprotocol/go-sdk` | 官方 Go SDK |

### 数据仓布局

```
my-infra/
├── infrafile.yaml            # 仓库配置：apiVersion、凭据后端、启用的插件
├── inventory/
│   ├── servers/web1.yaml     # 目录名 = kind 的复数小写，文件名 = metadata.name
│   ├── apps/
│   ├── domains/
│   ├── accounts/
│   ├── resources/
│   └── repos/
├── state/                    # 只有机器写
│   ├── _sync.yaml
│   └── cloudflare/example-main.yaml
├── secrets/                  # sops 加密文件
│   └── servers.enc.yaml
└── .sops.yaml
```

文件名必须等于 `metadata.name`，否则校验报错。

## 里程碑

### M0 仓库骨架 ✅

`go.mod`、CLI 入口（`version` / `help`）、CI（gofmt + vet + test）、goreleaser、LICENSE、贡献指南。

### M1 账本核心 ✅

- 六种 kind 的 schema，以 JSON Schema 文件形式内嵌进二进制；外键用自定义关键字声明（如 `x-ref: Account`）。
- 加载器：遍历 `inventory/`，解析信封，按 kind 建索引。
- `infrafile validate`：结构校验 + 外键完整性 + 文件名一致 + 归档引用检查 + `--base` 防删除。
- `infrafile schema export`：导出 JSON Schema，供编辑器补全和外部工具使用。
- `infrafile init`：生成数据仓骨架。
- 明文凭据检测：`secrets` 字段只接受 URI；对其他字段做常见 token 格式的启发式扫描，命中即报错。
- `examples/homelab` 补上覆盖六种 kind 的虚构数据。

**完成标准**：`infrafile validate examples/homelab` 通过；故意破坏外键、删除记录、写入明文 token 的夹具都能被拦下，退出码非零。

### M2 查询与生成 ✅

- `infrafile show <name|Kind/name> [目录]`：取单条记录（含归档），并列出入边和出边（谁引用它、它引用谁）；跨 kind 同名时必须指定类型。
- `infrafile expiry [目录] [--within 30d]`：到期检查。2026-10-25 确认：0 无到期项；1 有已过期或阈值内到期项；2 用法错误或无法执行。按本地日历日计算，包含今天和阈值当天，忽略归档记录及未填写到期日的记录。
- `infrafile ssh-config`：从 Server 记录渲染 SSH config 片段。

三个命令均先校验整个数据仓，校验未通过时退出 2 且 stdout 为空。`ssh-config` 只输出在用 Server，未填写的 SSH 用户和端口沿用 SSH 本身的默认配置；不写文件、不连接主机。

**完成标准**：三个命令的文本输出和 `--json` 输出都由黄金测试锁定。

### M3 凭据 ✅

- 统一的引用解析接口，三种后端：`sops://`、`op://`、`env://`。
- `infrafile secret check`：确认所有引用都能解析到，不解密。
- `infrafile run --secret NAME=<ref> -- <cmd>`：注入到子进程环境变量。
- 测试用临时生成的 age 密钥加密夹具，仓库里不放任何真实密钥。

**完成标准**：`run` 的测试证明明文只出现在子进程环境里，不在主进程的 stdout / stderr，也不写任何文件。

实现边界：SOPS 引用沿用示例的 `sops://文件#字段路径`，支持仓内单组 age YAML；`secret check` 不请求凭据值，op 仅查询字段 ID。`run` 遮盖子进程输出中的完整原值，保留退出码；JSON 模式把子进程日志送到 stderr。具体约定见[凭据指南](../secrets.md)。SOPS v3.13.3 要求最低 Go 1.25.8，已同步更新 `go.mod`。

### M4 插件宿主 ✅

- 协议：JSON-RPC 2.0 over stdio，`describe` 握手，能力有 sync / probe / control / import。协议的 JSON Schema 放在 `protocol/` 目录。
- 宿主：发现插件（内置的和 `PATH` 上的 `infrafile-plugin-*`）、超时、错误隔离、快照 deny-list 校验。
- `infrafile sync [插件]`：执行 sync 并写入 `state/`。
- 内置插件走同一套接口（进程内实现），确保内外契约一致。
- 附一个最小的外部插件示例，用 shell 或 Python 写，证明跨语言可行。

**完成标准**：外部示例插件和内置插件都能跑通 `sync`；插件写敏感字段会被 deny-list 拦下。

实现约定：`plugins.<名称>.instances.<实例>` 显式启用，实例值直接作为配置；内置名称优先，其余按启用名从 PATH 发现。`sync [插件] --dir <目录> --timeout 30s` 逐实例执行，失败隔离、保留旧快照；退出 0 全部成功、1 实例失败、2 命令无法执行。协议采用逐行 JSON-RPC，JSON Schema 和 Python 示例随仓库发布；细节见[插件指南](../plugins.md)及 [JSON 契约](../json/sync.md)。

### M5 第一方插件 ✅

1. 通用探测：DNS、TLS 到期、WHOIS、SSH 实测（只读命令，带超时）。
2. Cloudflare：读 zone、DNS 记录、代理状态。
3. 阿里云、腾讯云、百度云：列出注册域名和 CDN。天翼云先列出 CDN；2026-10-25 用户确认注册域名暂不支持，因为公开文档和官方 SDK 中未找到可核验的注册域名列表 API。

各云插件用 HTTP 响应夹具离线回放，CI 不访问真实云。本阶段夹具来自官方公开响应结构的虚构改写及合成边界用例，未抓取真实账号响应；来源见[夹具说明](../../internal/plugin/testdata/README.md)。通用探测使用内存 DNS、本地 TLS / WHOIS 和模拟 SSH 进程。

**完成标准**：每个插件都有离线夹具测试；README 写明每个插件需要的权限及已知授权缺口。签名向量、分页、错误隔离、凭据反射拒绝、CLI JSON 与快照写入均有覆盖；真实云账号和实际 IAM 权限未验收。

实现边界：九个内置名称复用 `sync`；凭据引用在显式同步时解析；不引入云 SDK 或新增依赖模块。为使 SOPS 密钥命令遵守超时，复用依赖图中已有的 shlex 和 SOPS / age 库，明确非交互身份范围。`services` 按需选择注册域名或 CDN，天翼仅允许 CDN 并返回 `unsupported: [registered-domains]`。百度 BCD 精确 IAM policy 名称和天翼 EOP 精确 IAM action 尚未由公开文档确认，不能声称已验证最小授权。详情见[配置指南](../first-party-plugins.md)和 README 权限表。

### M6 导入 ✅

- `infrafile import ssh-config`：从 `~/.ssh/config` 生成 Server 记录草稿。
- `infrafile import state`：从 `state/` 生成记录草稿，**只建不覆盖**，已存在的记录一律跳过。
- 草稿默认输出到 stdout 或一个待审目录，加 `--write` 才写进 `inventory/`。

**完成标准**：对已存在的记录重复导入，不会修改任何文件。

2026-10-25 确认的 state 映射：注册域名 / WHOIS → Domain，CDN / Cloudflare DNS zone → Resource，SSH → Server；DNS / TLS 仅作观测，明确报告跳过。实现复用 Schema 和敏感字段检测，不自动创建 Account 或推断外键。`--dir` 指定台账，SSH 的 `--file` 可覆盖默认输入；默认 stdout 多文档 YAML，`--output` 为待审目录，与 `--write` 互斥。完整候选预检后才写；单文件完整发布且不替换已有名字。相同主键的新增候选冲突会报错，重复导入保留已有内容、归档和修改时间。SSH 支持 Include、字面 Host、多别名、通配默认项及首值优先；不执行 Match、地址规范化或任何命令。详情见[导入指南](../import.md)和 [JSON 契约](../json/import.md)。

### M7 受控写 ✅

- `infrafile plan <动作>` 生成计划文件，`infrafile plan show` 渲染计划内容。
- `infrafile apply <计划文件>`：回读观测状态，与计划里记录的哈希比对，不一致就拒绝执行；执行后再回读确认。
- CDN 写操作（暂停、恢复、改回源）走插件的 control 能力；第一版先接 Cloudflare。
- `infrafile dnscontrol`：从台账生成 DNSControl 配置，不直接写 DNS。

**完成标准**：用模拟插件测试三种情况：状态未变时成功执行、状态已变时拒绝执行、执行后回读不符时报错。

2026-10-25 确认：Cloudflare 暂停／恢复作用于整个 zone；改回源只修改已存在且启用的 Origin Rule 的目标 host（需 Enterprise），DNS 记录不由 control 修改。Resource.spec.control 显式绑定已启用插件实例和远端 ID；v1 每份计划一个动作，包含前后状态、观测与台账／配置哈希，apply 再回读。失败不自动重试或回滚，GET 与 PATCH 之间不是原子 CAS。Domain.spec.dns 新增 provider 与显式 A / AAAA / CNAME / MX / TXT / NS / CAA 记录，DNSControl 输出固定 NO_PURGE。行为、权限和局限见[指南](../control.md)；JSON 契约与黄金测试随命令提供。本阶段仅离线回放，未执行真实云写入。

### M8 Agent 接口 ✅

- `infrafile mcp`：本地 stdio MCP 服务。只读，加上生成 dry-run plan；参数只接受主键和标签；不返回明文。
- `infrafile agent guide` / `agent install`：内嵌的指南随版本发布。
- 整理 `docs/json/`，作为 `--json` 输出的契约文档。

**完成标准**：MCP 测试覆盖「用原始 IP 请求被拒绝」和「任何工具的返回值里都不含夹具中的明文」。

实现提供 list / show / expiry / validate / schema / plan 六个工具，启动时固定台账目录，参数由内嵌 Schema 派生并严格校验。2026-10-25 确认：改回源只接受在用 Server / Resource / Domain 主键，分别从 address / endpoint / 域名解析合法主机名；不接受 IP 或 URL，标签目标必须唯一。MCP 仅生成计划，不写文件、不提供 apply；查询不解析凭据。指南以项目技能形式安装到 Codex `.agents/skills/infrafile` 或 Claude Code `.claude/skills/infrafile`，相同内容不重写，不同内容保留并报错。离线测试和黄金契约覆盖 stdio、选择约束、超时取消、凭据边界及安装行为；未进行真实云账号或桌面客户端加载验收。详见[Agent 指南](../agent.md)和 [MCP 契约](../json/mcp.md)。

### M9 发版（进行中）

- goreleaser 加签名（建议用 cosign keyless，基于 GitHub OIDC，不需要保管密钥）。
- 建 `infrafile/homebrew-tap` 仓库，formula 里附带 `ifl` 软链。
- 按 `examples/homelab` 写一份快速上手文档。
- 打 `v0.1.0` 标签。

**完成标准**：`brew install infrafile/tap/infrafile` 装上后，`infrafile` 和 `ifl` 都能用，快速上手文档能照着从头跑通。

发布采用两步：Actions 用 GitHub OIDC 生成带 Cosign bundle 的草稿 Release；维护者验签与上手验证后公开 Release，并提交同批生成的 Homebrew formula。GoReleaser 2.19 的旧 brews 配置已弃用，改由标准库 Python 脚本从发布校验和生成 formula，保留原定安装命令和 ifl 软链。验收步骤见[发布指南](../release.md)。
