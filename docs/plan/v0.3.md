# v0.3 实现方案：观测可信

**状态（2026-10-28）**：方案已按现有代码和真实使用验收细化，开始 M0；其余里程碑尚未实现。v0.2.0 仍是正式版本。本方案不授权生产配置变更或权威台账切换。

## 目标与范围

让用户区分「发现偏差」「本轮采集失败」「证据不足，不能判断」。继续使用 Go 单二进制、离线 audit、稳定 CLI JSON 与只读 MCP；不新增模块依赖。

本版包含：同步执行回执、带明确范围和历史存在证据的 missing、CDN 回源漂移、App 绑定的源站暴露检查，以及遗留路径边界修复。Web UI、多用户、自动修复、自动云写、通知与监控引擎不在本版。

私有主台账迁移和日常运行是独立使用工作：工具仓只保留虚构夹具。迁移不能用编造 remote、归档日期、资源 ID 或批量豁免消除缺口。

## 证据与兼容原则

- inventory 永远由人维护；sync 只写 state。audit 不联网、不解析凭据、不写盘。
- 保留 `state/_sync.yaml` 的 v0.2 格式与含义：每实例最近一次成功同步的命令开始时间。插件失败不推进此时间，不覆盖旧快照。
- 新增 `state/.sync-status.yaml`，每实例只保留最近一次执行回执。隐藏文件名是兼容选择：v0.2 的快照读取器会跳过它，旧版仍可读原快照和成功时间，但不能理解新执行状态。
- 回执不是签名或云端权限证明。内容哈希只用于发现错配，不证明远端完整性。旧版 sync、人工修改快照或配置变化后，不能沿用回执认定证据完整。
- 没有 v0.3 回执的旧仓继续可用；不能凭旧快照直接执行新的负向缺失判断。
- JSON `version: v1` 保持不变，M0 不改变已有字段或退出码；audit 新增提示码属于兼容扩展。新增规则必须同时更新 schema、规则注册表、CLI/MCP 契约、Agent 指南及黄金测试。

## M0 同步执行回执

回执信封为 `apiVersion: infrafile/v1alpha1`、`kind: SyncStatus`；`spec` 按 plugin / instance 索引。每条回执包含：

| 字段 | 含义 |
| --- | --- |
| attempted_at | 本次命令开始时间，UTC RFC3339，与现有成功时间口径一致，不冒充请求完成时间 |
| status | running / succeeded / failed |
| config_hash | 实例配置的稳定 JSON SHA-256；只散列引用，不解析认证值 |
| snapshot_hash | 仅 succeeded 有：已落盘快照字节的 SHA-256 |
| code | 仅 failed 有：固定错误分类；不保存错误原文、日志、响应或凭据 |

执行顺序：获取现有 `.sync.lock` → 校验已有状态文件 → 原子保存 running → 调用插件 → 保存快照与成功时间 → 原子保存 succeeded / failed。结果没有变化也更新回执和成功时间，不重写快照。未执行的实例不记成功；取消记录当前实例失败，随后停止。

开始回执保存失败时，不调用该实例插件。结束回执保存失败时，返回 write 失败并停止后续实例，running 保留为不完整证据。跨文件写入不是事务；断电或强杀可能留下锁，确认无同步运行后才能手动解锁。

读取器与写入器共用严格解析：拒绝符号链接、损坏信封、重复键、多文档、未知字段、非法时间/状态/错误码/哈希和不一致字段组合；沿用 YAML 展开限制，回执最多 4 MiB。错误只返回固定说明，不回显输入。

audit 对启用实例检查回执，包括没有快照的首次失败：

- `sync_failed`：当前配置最近一次执行失败，旧快照仍是历史证据。
- `sync_incomplete`：最近执行只有 running 回执。
- `sync_status_unverified`：配置、成功时间或快照哈希不对应，或状态文件存在但该实例没有回执。

以上为 notices，不改变既有 audit 的 ok / 退出码，也不屏蔽 v0.2 规则的历史发现；自动化仍须检查 sync 退出码。只有成功且与配置、时间、快照都对应的回执，才可作为 M1 的执行前提。

**验收**：成功→失败→恢复；首次失败无快照；超时/取消；部分实例失败隔离；敏感输出拒绝；快照或时间写入失败；回执损坏/符号链接/写入失败；旧仓可读；新回执被旧读取方式跳过；CLI/MCP 离线审计看见同一执行状态。

## M1 missing：查询范围内不再可见

只检查显式声明的目标，先在 config 增加 `audit.watch`，每项为 `{target, plugin, instance, service}`。target 是在用记录主键，不接受地址、模糊匹配或标签；实例必须启用，service 必须被该插件支持且在本次配置范围内。绑定与自然身份复用现有映射，不根据厂商名猜账号。

为避免新录入误报，第一次成功采集只能建立正向基线。sync 在 `state/.presence.yaml` 保存该目标确实出现过的证据，绑定目标自然身份、watch、实例配置哈希和 last_seen。身份/绑定/配置变化使旧基线失效；baseline 写失败同样不能取得缺失判断资格。不回写 inventory，不从文件 mtime 推断创建时间。

仅当回执成功且完全对应、提供非负 `--max-age` 且证据未过期/不在未来、已有同一绑定的正向基线、本次对应集合完整返回却不再包含目标时，才报 missing。没有基线、未采集服务、实例失败、范围不明、旧版同步、损坏/过期/未来证据均不报 missing，并提示不能判断；损坏文件仍退出 2。

finding 的语义是「在指定凭据的本次查询范围内未找到」，不能断言资产已删除。凭据权限变窄且 API 未报错时无法自动区分权限变化与删除，消息必须明确要求核对权限和范围。第一版只覆盖云清单的注册域名、CDN、Cloudflare zone；SSH/DNS/TLS/WHOIS 不推断远端资产缺失。规则与豁免按已声明目标精确匹配。

**验收**：新录入不报；先见到再消失才报；再出现恢复；配置/身份变化失效；部分服务、空清单、失败保旧、旧回执、超时、权限错误与多账号隔离；CLI/MCP/豁免一致。

## M2 CDN 回源漂移

新增显式的期望回源字段 `spec.origin`；比较源站主机集合，以及用户显式声明且供应商可采集的端口、协议。域名大小写/尾点和 IP 规范化，集合排序去重；不推断省略字段的厂商默认值。敏感回源鉴权不进入快照。

先逐家核对官方接口、分页、请求预算和最小只读权限，再冻结该厂商字段映射与夹具；阿里、腾讯、百度、天翼及 Cloudflare Origin Rule 分批完成。多源站、按地区/规则匹配、缺失端口或不支持的字段必须保留 unknown，不能压成单个 host 或写成默认正常。

按需显式启用回源采集，避免给现有清单同步暗中增加逐域名请求与权限。每实例仍受统一超时、分页和响应上限约束。只有新鲜、匹配且支持相应字段的证据产生回源漂移；查询失败不覆盖旧观测。复用 cdn_drift 的 Resource 目标和记录级豁免，evidence 区分停用与回源偏差。云端写入能力不随此功能扩展。

**验收**：每家完成映射前不宣称支持；主机/端口/协议差异、顺序差异、多源站、规则范围、鉴权裁剪、超时/权限不足均有夹具。实际只读验收与正式写入验收分开记录。

## M3 App 绑定源站暴露

将仅绑定 App 的在用 Domain 展开到 App 的全部在用 Server 部署；多部署逐一比较，不任意选一台。继续只比较明确登记的地址与台账 DNS、Cloudflare、DNS 快照证据，不查端口、不沿 CNAME 自动追踪。

显式 Server/Resource 绑定仍优先，归档记录排除，共享部署去重，豁免仍属于 Domain。无部署或不能确定地址时输出不能判断的提示。覆盖多部署、混合归档、Resource 优先级、IPv4/IPv6、重复证据和豁免隔离。

## M4 路径边界与使用接入

统一拒绝 `inventory/` 根目录和 `infrafile.yaml` 本身的符号链接，与现有 kind/记录文件边界一致；测试覆盖 CLI 直接调用者。核实导出 JSON Schema 的凭据正则在编辑器中的兼容性，不能以削弱运行时校验作为兼容办法。

用私有台账完成真实身份映射、定时采集与离线 CI 审计、桌面 MCP 接入验证。Gatus 持续监控/通知属于使用方集成验收，不在工具里另造引擎；完整台账切换单独保留映射、缺失项和回退点。

## M5 发布验收

每个里程碑先完成直接测试与调用者检查；最终统一跑一次 make check、离线上手和打包预检。合入以最终提交 CI 为准，发版遵循 release.md，不能把源码构建或私有验收投影称作正式发布。

保留成功/失败/unknown 三类虚构示例，说明 v0.2 读取新数据的能力边界。真实凭据、资产、快照和接口响应不进入公开仓库。线上 apply、Origin Rules 授权、IAM 最小权限、原生平台与监控告警分别标注已验证范围。

## 实施顺序与影响面

M0 → M1 → M2 / M3 → M4 → M5。M2 可以按厂商拆分交付，但不能在未核对接口时宣称完整支持；若最终版本需裁剪范围，先更新本方案与验收目标。

本轮先完成 M0 的可独立审阅增量：`internal/plugin` 状态写入与宿主调用、`internal/snapshot` 回执读取、`internal/audit` 离线提示，及其 CLI/MCP 测试、存储/JSON/Agent 文档。M1–M5 保持明确待办，不提前加入未实现规则或字段。
